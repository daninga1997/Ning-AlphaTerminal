# Alpha Terminal Design System

产品名称：Alpha Terminal  
副标题：AI Trading Workspace  
版本：Sprint 01  
状态：设计系统规范与 Token 层，不包含业务页面改造

---

## 1. 设计目标

Alpha Terminal 的设计系统服务于一个专业金融终端，而不是普通信息网站。

核心目标：

1. Less is More：减少视觉噪音，突出交易判断。
2. 大量留白：让高密度信息仍然可扫描。
3. 信息密度高：每个组件都应承载清晰用途。
4. 视觉不拥挤：不通过堆叠颜色、边框和阴影制造复杂感。
5. 专业克制：避免娱乐化、门户化和情绪化刺激。

风格参考：

- TradingView：图表与行情阅读纪律。
- Bloomberg：专业金融终端的信息信任感。
- Linear：清晰层级与低噪音界面。
- Apple：可理解性、克制反馈、精确交互。
- Notion：模块化内容组织和阅读舒适度。

## 2. Color

### 2.1 颜色原则

颜色只表达状态，不做装饰。

金融终端中，颜色必须克制使用：

- 绿色表示可行动、正向或上涨。
- 红色表示风险、负向或下跌。
- 黄色表示等待、警告或不确定。
- 蓝色表示当前选择、信息聚焦或系统主色。
- 灰色表示背景、边界、辅助文字和禁用状态。

### 2.2 语义色

| Token | 用途 | 色值 |
|---|---|---|
| Primary | 主操作、焦点、当前导航 | `#4F8CFF` |
| Success | 可行动、上涨、可以买 | `#22C55E` |
| Warning | 等待、谨慎、条件未满足 | `#F59E0B` |
| Danger | 风险、下跌、回避、止损 | `#EF4444` |
| Background | 页面背景 | `#090A0D` |
| Card | 卡片背景 | `#111318` |
| Border | 主要边框 | `#252A33` |
| Text | 主文字 | `#F4F7FB` |
| Secondary Text | 辅助文字 | `#8B95A7` |
| Divider | 分割线 | `#1A1F27` |
| Hover | 悬停背景 | `#171C24` |
| Active | 激活背景 | `#1D2633` |
| Focus | 焦点描边 | `#7AA7FF` |

### 2.3 使用规则

1. 页面背景必须使用深色背景，不使用纯黑。
2. 卡片与页面背景之间使用轻微明度差，不依赖强阴影。
3. 边框用于建立结构，不用于装饰。
4. 文本颜色最多分为主文字、辅助文字、弱文字三层。
5. 红绿只用于状态，不用于大面积背景。

## 3. Typography

### 3.1 字体原则

Alpha Terminal 需要同时满足中文阅读、英文金融术语、数字表格和股票代码展示。

推荐字体栈：

```text
Inter, "SF Pro Display", "SF Pro Text", "PingFang SC",
"Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif
```

数字字体推荐：

```text
"SF Mono", "Roboto Mono", "JetBrains Mono", Consolas, monospace
```

### 3.2 字体规范

| 类型 | 字号 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| Page Title | 28px | 36px | 650 | 页面标题 |
| Section Title | 20px | 28px | 600 | 模块标题 |
| Card Title | 16px | 24px | 600 | 卡片标题 |
| Subtitle | 14px | 22px | 500 | 副标题、说明 |
| Body | 14px | 22px | 400 | 正文 |
| Small Body | 13px | 20px | 400 | 紧凑说明 |
| Caption | 12px | 18px | 400 | 辅助信息 |
| Label | 12px | 16px | 600 | 标签、字段名 |
| Button | 14px | 20px | 600 | 按钮 |
| Number | 16px | 22px | 600 | 普通数字 |
| Large Number | 24px | 30px | 650 | 核心数字 |
| Stock Code | 12px | 16px | 500 | 股票代码 |
| Percent | 14px | 20px | 650 | 涨跌幅 |

### 3.3 数字规范

1. 价格、涨跌幅、成交额、评分必须使用等宽数字。
2. 数字列右对齐。
3. 正负百分比必须带符号。
4. 不用过大的数字制造情绪冲击。

## 4. Spacing

### 4.1 间距刻度

统一使用以下间距：

| Token | 值 | 用途 |
|---|---:|---|
| 4 | 4px | 图标间距、紧凑元素 |
| 8 | 8px | 小型组件内部间距 |
| 12 | 12px | Badge、Tag、输入区紧凑间距 |
| 16 | 16px | 卡片内部基础间距 |
| 20 | 20px | 卡片组间距 |
| 24 | 24px | 模块间距 |
| 32 | 32px | 页面区域间距 |
| 40 | 40px | 大区块间距 |
| 48 | 48px | 页面主结构间距 |
| 64 | 64px | 大屏留白 |

### 4.2 使用规则

1. 小组件内部优先使用 8、12、16。
2. 卡片之间优先使用 16、20、24。
3. 页面区块之间优先使用 32、40、48。
4. 不引入随意间距值。

## 5. Radius

| Token | 值 | 用途 |
|---|---:|---|
| Card Radius | 8px | 卡片、面板 |
| Button Radius | 6px | 按钮 |
| Input Radius | 6px | 输入框、搜索框 |
| Badge Radius | 999px | Badge、Tag、Signal |

使用规则：

1. 金融终端不使用过度圆润的卡片。
2. Card Radius 不超过 8px。
3. 只有 Badge、Tag、Signal 允许胶囊形态。

## 6. Shadow

阴影只用于层级，不用于装饰。

| Token | 用途 | 值 |
|---|---|---|
| Card Shadow | 卡片轻微浮起 | `0 1px 2px rgba(0, 0, 0, 0.24)` |
| Popup Shadow | Modal、Drawer、Tooltip | `0 16px 40px rgba(0, 0, 0, 0.42)` |
| Hover Shadow | 可点击卡片悬停 | `0 8px 24px rgba(0, 0, 0, 0.28)` |

使用规则：

1. 默认界面尽量依靠背景、边框和留白建立层级。
2. 阴影只在弹层、悬停和高层级浮层中使用。
3. 不使用彩色阴影。

## 7. Components

本节定义组件规范，不代表本 Sprint 要实现组件。

### 7.1 Button

用途：明确命令。

类型：

- Primary：主操作。
- Secondary：次级操作。
- Ghost：低强调操作。
- Danger：风险操作。

规则：

1. 按钮文字必须是动词或明确命令。
2. 一个区域最多一个 Primary Button。
3. 禁止使用夸张渐变按钮。

### 7.2 Card

用途：承载一个完整判断单元。

规则：

1. 每张卡片必须有明确主题。
2. 卡片内不嵌套卡片。
3. 金融数据卡片优先使用紧凑布局。

### 7.3 Badge

用途：表达状态、等级、类别。

规则：

1. Badge 不承载长句。
2. Badge 必须有明确语义色。
3. 同一区域 Badge 数量应克制。

### 7.4 Tag

用途：板块、主题、筛选条件。

规则：

1. Tag 用于分类，不用于交易信号。
2. 可选 Tag 需要有 Hover 和 Active 状态。

### 7.5 Signal

Signal 是交易行为状态，必须全局统一。

| Signal | 中文 | 颜色 | 含义 |
|---|---|---|---|
| buy | 可以买 | Success | 条件满足，可进入计划执行 |
| wait | 等待 | Warning | 条件未确认，等待触发 |
| hold | 持股 | Primary | 已在计划内，继续跟踪 |
| reduce | 减仓 | Warning | 风险上升，降低仓位 |
| avoid | 回避 | Danger | 条件失效或风险过高 |

规则：

1. Signal 只能使用以上五种。
2. Signal 必须显示中文含义。
3. 不能新增近义状态，例如“强烈买入”“必买”。

### 7.6 Progress

用途：表达评分、完成度、强弱程度。

规则：

1. Progress 必须有数值标签。
2. 高风险项不能只用绿色进度条表达。
3. 分数进度条不应过粗。

### 7.7 Score

用途：展示短线评分、中线评分、综合评分。

规则：

1. Score 必须展示分数和等级。
2. Score 必须可追溯分项。
3. Score 高分不等于买入指令。

### 7.8 Input

用途：普通输入。

规则：

1. 输入框高度统一。
2. 必须有 Focus 状态。
3. 错误信息显示在输入框附近。

### 7.9 Search

用途：搜索股票名称、代码、报告、新闻。

规则：

1. Search 必须支持清空。
2. 搜索结果为空时显示 Empty 状态。
3. 搜索框不承担筛选器全部功能。

### 7.10 Modal

用途：需要用户聚焦处理的短任务。

规则：

1. Modal 只用于确认、编辑、关键说明。
2. 禁止在 Modal 中承载复杂页面。
3. 必须提供明确关闭方式。

### 7.11 Drawer

用途：右侧辅助信息、筛选面板、详情预览。

规则：

1. Drawer 不替代主页面。
2. Drawer 宽度必须受控。
3. 移动端 Drawer 可转为底部面板。

### 7.12 Tabs

用途：同一上下文内切换信息。

规则：

1. Tabs 不超过 5 个。
2. Tab 名称必须短。
3. 不用 Tabs 隐藏关键结论。

### 7.13 Table

用途：高密度对比信息。

规则：

1. 表格只用于桌面端高密度场景。
2. 移动端必须转为卡片或列表。
3. 数字列右对齐。
4. 表头必须支持清晰排序状态。

### 7.14 List

用途：报告、新闻、事件流。

规则：

1. 列表项必须有标题、摘要、状态和时间。
2. 列表项间距保持紧凑但可读。

### 7.15 Empty

用途：无结果、无数据、无机会。

规则：

1. Empty 必须说明原因。
2. 不使用幽默化文案。
3. 交易场景中应允许显示“今日不开仓”。

### 7.16 Loading

用途：短时加载。

规则：

1. Loading 文案必须说明加载对象。
2. 长时间加载需要提供异常或重试状态。

### 7.17 Skeleton

用途：页面初始加载占位。

规则：

1. Skeleton 应匹配真实布局。
2. 不使用过强闪烁。

### 7.18 Tooltip

用途：解释短标签、图标、评分项。

规则：

1. Tooltip 文案必须短。
2. 不在 Tooltip 中放关键交易结论。
3. 移动端需要替代交互。

### 7.19 Avatar

用途：用户、模型、数据源身份。

规则：

1. Avatar 不作为装饰。
2. AI 头像必须与人工用户区分。

## 8. Icon

### 8.1 图标原则

1. 全项目使用同一图标体系。
2. 图标必须服务识别，不做装饰。
3. 同一个含义只能使用一个图标。
4. 图标线宽、尺寸、圆角必须统一。

### 8.2 尺寸

| Token | 值 | 用途 |
|---|---:|---|
| Icon XS | 12px | 表格、标签内图标 |
| Icon SM | 16px | 按钮、输入框 |
| Icon MD | 20px | 导航、卡片标题 |
| Icon LG | 24px | 空状态、模块标题 |

### 8.3 使用规则

1. 默认图标尺寸为 16px。
2. 按钮内图标与文字间距为 8px。
3. 图标颜色继承文字颜色。
4. 不混用实心图标和线性图标。

---

## 9. Animation

### 9.1 动效原则

动效只用于反馈和状态转换，不用于吸引注意。

### 9.2 时长

| Token | 值 | 用途 |
|---|---:|---|
| Fast | 120ms | Hover、轻反馈 |
| Normal | 180ms | 普通状态切换 |
| Slow | 240ms | Modal、Drawer |

### 9.3 缓动

统一使用：

```text
cubic-bezier(0.2, 0, 0, 1)
```

### 9.4 禁止项

1. 禁止花哨入场动画。
2. 禁止循环闪烁吸引交易注意。
3. 禁止弹跳、旋转等娱乐化效果。
4. 禁止大面积渐变流动背景。

## 10. Layout

### 10.1 全局布局

| Token | 值 | 用途 |
|---|---:|---|
| Header Height | 56px | 顶部导航 |
| Sidebar Width | 240px | 未来侧栏或设置导航 |
| Right Rail Width | 320px | 右侧信息栏 |
| Container Max | 1440px | 桌面最大内容宽 |
| Content Padding Desktop | 32px | 桌面页面内边距 |
| Content Padding Mobile | 16px | 移动端页面内边距 |
| Card Min Width | 280px | 卡片最小宽度 |
| Card Ideal Width | 360px | 卡片建议宽度 |

### 10.2 Grid

桌面：

- 12 列网格。
- 列间距 24px。
- 页面最大宽度 1440px。

Laptop：

- 12 列网格。
- 列间距 20px。

Tablet：

- 8 列网格。
- 列间距 16px。

Mobile：

- 4 列网格。
- 列间距 12px。

### 10.3 页面布局规则

1. 一级页面优先使用顶部导航。
2. 右侧栏只放辅助信息，不放主决策。
3. 页面第一屏必须包含当前页面最重要结论。
4. 不使用装饰性大 Hero。

## 11. Responsive

### 11.1 Breakpoints

| Token | 宽度 | 设备 |
|---|---:|---|
| Mobile | 0-639px | 手机 |
| Tablet | 640-1023px | 平板 |
| Laptop | 1024-1279px | 笔记本 |
| Desktop | 1280px+ | 桌面 |

### 11.2 Desktop

1. 支持高密度表格和多列卡片。
2. 保留右侧辅助栏。
3. 允许复杂筛选器横向展示。

### 11.3 Laptop

1. 减少右侧辅助栏宽度。
2. 保持主内容优先。
3. 卡片列数可从 3 列降为 2 列。

### 11.4 Tablet

1. 优先卡片布局。
2. 筛选器可折叠。
3. 表格转为简化表格或卡片。

### 11.5 Mobile

1. 禁止强行压缩桌面表格。
2. 所有交易状态必须可单手阅读。
3. 关键操作按钮必须足够大。
4. 详情页按垂直顺序展示结论、计划、依据、指标、图表。

## 13. 使用边界

Sprint 01 只建立设计系统，不修改任何页面。

本阶段不做：

1. 不改 Dashboard。
2. 不改 Watchlist。
3. 不改业务逻辑。
4. 不改评分算法。
5. 不接行情。
6. 不接数据库。
7. 不接 AI。
8. 不实现实际组件。

后续 Sprint 若要应用设计系统，必须先确认目标页面和改造范围。
