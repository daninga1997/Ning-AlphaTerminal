# 模拟交易完整闭环设计

**日期：** 2026-08-03
**状态：** 已确认，待实现
**范围：** Alpha Terminal 的新模拟交易账户、订单与自动退出闭环。旧 `PaperTrade` 仅保留为只读历史，不迁移、不改写。

## 1. 目标与边界

本设计建立一个可审计、可恢复、遵守 A 股交易约束的模拟交易账户。它基于 Alpha Terminal 既有策略、行情和分钟 K 线工作，但不连接券商、不产生真实订单，也不设计 `BrokerExecutionProvider`。

系统的写入入口只有 `PaperTradingCommandService`。页面、Codex MCP 和后台 Worker 都通过该服务提交命令；它们不得直接写数据库。查询可以通过只读 Query Service 或 API 返回，但查询结果不能被当作写入权限。

## 2. 账户与账本模型

100,000.00 元是**以后新建账户**的默认初始资金。账户模板设置允许用户调整这个默认值以及佣金、印花税、过户费、风险上限和仓位上限；调整默认初始资金不改写任何已有账户的初始资金、余额或账本。已有账户需要入金、出金或更正资金时，只能通过不可变的 `CashLedgerEntry` 资金流水完成，且必须记录调整原因、操作者、发生时间与对应 `PaperAuditLog`。每次设置变更均记录版本、操作者、时间和变更前后值；已成交订单使用成交时生效的费率快照，不因后续设置变化而重算历史账目。

新账户由以下记录组成：

| 记录 | 责任 |
| --- | --- |
| `PaperAccount` | 账户余额、可用现金、冻结现金、账户设置版本和账户状态。 |
| `PaperPosition` | 每只股票唯一的汇总持仓；记录总持仓、可卖持仓、冻结持仓、加权成本、当前保护计划和持仓状态。 |
| `PaperLot` | 每一次买入成交形成一个批次；记录可卖日期、剩余数量、成本和批次状态，用于 T+1 与成本追溯。 |
| `PaperOrder` | 用户确认后的开仓、加仓、减仓、平仓、止盈或止损订单；具有状态机、风控快照和幂等键。 |
| `PaperFill` | 每笔模拟成交；记录触发来源、价格、数量、分钟 K 线、费用和成交前后账户快照引用。 |
| `CashLedgerEntry` | 不可变资金流水，分别记录冻结、解冻、买入占款、卖出回款、佣金、印花税、过户费和调整。 |
| `ExitRule` | 经用户确认后生效的第一目标、第二目标、止损和失效条件。 |
| `PaperAuditLog` | 不可变审计日志，记录命令、确认、风控拒绝、Worker 决策和恢复行为。 |
| `PaperWorkerState` | Worker 租约、心跳、每个账户/股票的分钟线游标、最近成功检查时间和故障状态。 |

同一股票在同一账户只能有一条 `PaperPosition`。多次开仓或加仓创建多个 `PaperLot` 与 `PaperFill`，并更新同一汇总持仓；减仓和平仓按批次逐笔扣减并保留完整成交痕迹。

## 3. 指令、确认与权限

策略引擎只产生建议，不产生订单。建议包含建议股数、建议价格区间、止损、两档目标、风险计算依据、行情时间与策略版本。

用户可以修改建议股数。开仓和每次加仓都必须经过一次显式确认，确认界面必须展示：修改后的数量、预计占用现金、单股仓位、总仓位、预计最大亏损、费率、T+1 限制和风险例外（如有）。确认时重新读取账户与行情快照并重新风控；行情、现金、持仓、订单版本或风险条件发生变化时，订单进入 `requires_reconfirmation`，原确认不得继续成交，必须重新确认。

Codex MCP 只能提交与页面等价的“创建草稿”“确认订单”“取消订单”“确认加仓计划”命令。MCP 不拥有跳过确认、跳过风控、修改订单状态或直接写库的能力；所有命令都使用同一账户状态机、事务和审计日志。

## 4. 风控与仓位规则

默认风控规则如下：

1. 单一股票成交后市值不得超过账户净值的 30%。
2. 全账户已持仓市值加上待成交买单的最大可能市值不得超过账户净值的 80%。
3. 单笔风险默认不得超过账户净值的 2%。单笔风险定义为：`数量 × max(买入参考价 - 止损价, 0) + 预计买卖费用`。
4. 买入数量按 100 股整手向下取整；不足一手时默认拒绝创建可确认订单。

当按 2% 风险上限计算出的合法数量不足 100 股时，用户可以对**当次**订单确认“最小一手风险例外”。该例外只允许将数量提升至 100 股，并必须显示超过 2% 的实际最大亏损。它不持久化、不自动复用，且仍必须满足 30% 单股上限与 80% 总仓位上限；任一仓位上限不满足时不可例外成交。

减仓、平仓和自动退出不受买入仓位上限约束，但受可卖数量和 T+1 限制约束。

## 5. A 股 T+1 与冻结规则

买入成交所在交易日为 T。该成交生成的 `PaperLot` 在 T 日全部标记为冻结，不得参与任何卖出、止盈或止损成交。下一个有效交易日开始前，Worker 按交易日历将该批次转为可卖；转换是可重试且幂等的。

汇总持仓的可卖数量等于全部已解冻批次的剩余数量。卖出订单只可占用可卖数量；若目标、止损或手动卖出数量超过可卖数量，则仅为可卖部分创建订单，其余数量保持等待，不得绕过 T+1。系统在审计日志中写入“因 T+1 冻结未成交”的原因。

## 6. 费用与成交价格

费用在账户设置中独立配置并在成交时快照：

- 佣金默认双向 0.025%，每笔最低 5.00 元；
- 印花税默认仅卖出侧 0.05%；
- 过户费默认双向 0.001%，允许按账户设置单独调整；
- 滑点不作为隐藏费用。自动触发时按下文的正常触达或跳空规则确定成交价。

买入时冻结预计最大占款，成交后写入买入成交、佣金和过户费流水；未用冻结资金立即解冻。卖出时先校验可卖批次，成交后分别写入卖出回款、佣金、印花税和过户费流水。所有金额以分为最小数据库单位，展示时格式化为元，避免浮点误差。

## 7. 汇总持仓、加仓与退出计划

每笔买入成交更新汇总持仓的数量和含买入费用的加权成本。用户提出加仓时，AI/策略根据新的数量、成本、当前价和分钟线重新计算止损、第一目标和第二目标；只有用户确认新的退出规则后才替换当前 `ExitRule`。未确认前，原退出规则继续有效。

确认后的退出计划包含：

- 第一目标：触发时自动卖出当时可卖持仓的 50%；
- 第二目标：自动卖出第一目标执行后剩余的全部持仓；
- 止损：保护尚未卖出的可卖持仓；
- 计划版本和计算时使用的行情、策略、费用快照。

第一目标的卖出数量只以触发时的可卖持仓计算，T+1 冻结数量不参与本次成交。可卖数量大于 100 股时，卖出数量为 `floor(可卖数量 × 50% / 100) × 100`；可卖数量恰为 100 股时，直接卖出 100 股。可卖数量不足 100 股时不执行第一目标卖出，等待后续目标或最终清仓；最终清仓允许卖出不足 100 股的剩余零股。可卖部分成交后，其订单进入 `filled`；因 T+1 冻结而未能参与本次目标成交的数量创建或保留一个关联的 `pending_t1` 待退出订单。该订单在批次解冻后必须按当时新鲜行情和现行退出规则重新判断，不以旧分钟线或旧价补造成交。买入使用 100 股整手；除最终清仓零股外，卖出数量按 100 股向下取整。

第一目标成交后，系统重新计算剩余仓位的含费用保本止损价：以全部买入成本与已发生买入费用减去第一目标实际净回款，除以剩余数量，并纳入该剩余数量未来卖出时的佣金、印花税和过户费，求得不会使整笔交易净亏损的最小卖出价格。该价格高于原止损时，止损自动上移；低于原止损时保持原止损，不下调保护位。

## 8. 分钟线触发、跳空与双触发

Worker 只使用最新价和连续、可用的 1 分钟 K 线决定自动退出。每次检查按分钟时间顺序处理未消费 K 线，并更新游标。每根 K 线的处理顺序固定如下：

1. 校验行情状态为 fresh，且分钟线时间连续、未过期；否则暂停自动成交。
2. 先解除当日应解冻的 T+1 批次，再读取可卖数量。
3. 对同一持仓判断止损、第一目标、第二目标。若同一根 1 分钟 K 线同时触及任意止盈与止损，**止损优先**；该分钟内不再执行止盈。
4. 若开盘价已越过触发价，视为跳空，以该分钟 K 线的 `open` 作为首个可观察成交价；卖出止损的开盘价低于止损、卖出目标的开盘价高于目标均适用此规则。
5. 非跳空的正常触达以预设触发价成交：K 线 `low` 触及止损，以止损价成交；K 线 `high` 触及目标，以目标价成交。
6. 成交后在同一事务内更新订单、成交、批次、持仓、资金流水、退出规则和审计日志；随后才推进该 K 线游标。

止损订单优先于第一目标，第一目标优先于第二目标。第一目标已完成后才允许判断第二目标。每个自动订单均使用 `accountId + positionId + exitRuleVersion + triggerType + minuteTimestamp` 组成的幂等键，重复扫描不得产生重复成交。

## 9. 行情不可用与恢复

当最新价、1 分钟 K 线或其时间戳处于 delayed、stale、unavailable，或分钟线出现缺口时，系统暂停自动成交，并将持仓状态标为“自动执行暂停”。暂停期间不以旧价、日线、演示数据或估算价格代替分钟线成交。

数据恢复后，Worker 从最后成功游标之后补查遗漏的连续分钟 K 线。若缺失区间无法补齐，则保持暂停并记录缺口；只有缺口被补齐或用户明确取消该自动退出计划后，才恢复自动执行。补查依旧采用相同的时间顺序、跳空规则、双触发优先级和幂等键。

## 10. Worker、租约与恢复

独立 Paper Trading Worker 每 30 秒运行一次行情检查，并每 10 秒更新一次已持有租约的心跳。它不提供公网 HTTP 端口，只通过本地进程能力访问数据库、市场数据服务和命令服务。

Worker 在处理账户前获取可续租的租约。租约包含 `workerId`、取得时间、到期时间和心跳时间；心跳连续 45 秒未更新时租约失效，其他 Worker 才可接管。仅持有有效租约的 Worker 可以提交自动退出命令。Worker 在长处理过程中按 10 秒节奏更新心跳，失去租约后立即停止写入。租约、游标、订单状态和幂等键均在事务内检查，保证并发 Worker、重复任务和进程重启不会重复成交。

Worker 重启时读取 `PaperWorkerState`：先续租或重新获取租约，再从最后成功游标补查数据；对已存在的幂等键返回既有结果，对未完成命令按订单状态继续或安全标记为待人工处理。任何异常都记录审计日志和 Worker 状态，不吞掉异常后继续假定成交成功。

## 11. 数据库事务边界

以下操作必须使用单个数据库事务并以当前账户版本或等价的乐观并发条件提交：

| 场景 | 同一事务内必须完成的动作 |
| --- | --- |
| 初始化账户 | 创建账户、初始现金流水、默认设置版本和审计日志。 |
| 创建草稿 | 校验输入、保存建议/用户修改值和审计日志；不冻结资金。 |
| 确认买入或加仓 | 重读账户/持仓/行情/设置，执行风险检查，创建订单，冻结现金，写审计日志。 |
| 买入成交 | 校验订单与资金冻结，写成交、买入批次、汇总持仓、费用和资金流水，解冻差额，更新订单与审计日志。 |
| 确认退出规则 | 校验持仓与规则版本，创建新规则版本，废止旧规则，写审计日志。 |
| 自动或手动卖出成交 | 校验 T+1 和幂等键，扣减批次/汇总持仓，写成交、回款、费用、订单状态、保本止损更新和审计日志。 |
| Worker 租约/游标推进 | 原子校验租约、心跳、幂等键和游标；成交成功后才推进游标。 |
| 设置变更 | 创建设置版本并写审计日志；不改写历史成交费率快照。 |

任何事务失败时全部回滚，不允许留下“订单已成交但未扣现金”“资金冻结但无订单”“游标已推进但成交未入账”等中间状态。

## 12. 页面、MCP 与服务边界

Alpha Terminal 页面通过受认证的本地应用 API 调用 Command Service。Codex 使用本地 stdio MCP 调用同一 Command Service；MCP 不开放公网端口，不持有独立订单状态，也不访问数据库连接。Worker 通过内部命令接口调用相同服务。

命令服务的主状态机为：`proposed -> awaiting_confirmation -> confirmed -> executing -> filled`。可选状态为 `requires_reconfirmation`、`pending_t1`、`rejected`、`cancelled`、`failed` 和 `expired`。行情、现金、持仓、订单版本或风险条件变化时，已确认但尚未执行的订单必须转入 `requires_reconfirmation`，且不可使用旧确认直接成交；重新确认后才回到 `confirmed`。因 T+1 冻结无法卖出的退出订单进入 `pending_t1`，待批次解冻并重新校验行情和规则后才可进入 `executing`。`rejected`、`cancelled`、`failed` 与 `expired` 为终态；自动退出订单使用同一状态机，但触发来源为 Worker。任何状态跳转都必须验证前置状态、账户版本、风控和审计上下文。

## 13. 测试与验收范围

实现必须覆盖以下测试：

1. 单元测试：风险计算、仓位上限、费用、加权成本、保本止损、正常触达、跳空、双触发止损优先、T+1 与目标拆分。
2. 事务测试：买入、卖出、加仓、确认退出规则和失败回滚后的账本一致性。
3. 并发测试：重复确认、并发 Worker、租约丢失、重复 K 线与幂等键不重复成交。
4. MCP 契约测试：MCP 与页面调用相同命令模型；MCP 无法跳过确认、风控或直接写库。
5. Worker 恢复测试：重启、行情暂停、补查遗漏 K 线、游标恢复和状态一致性。
6. 回归测试：旧 `PaperTrade` 仅能读取，既有页面、行情、策略、分钟线和回测能力不被修改。

## 14. 自检结论

- 规则无未决占位符，所有关键行为均已明确。
- 初始资金、资金调整与费用规则无冲突：10 万元仅是新账户默认值，已有账户通过不可变流水调整；过户费默认双向 0.001%，成交时按费率快照结算。
- 风险规则的唯一例外已明确：风险仓位不足一手时，用户可逐次确认 100 股例外；它仍不能突破 30% 单股与 80% 总仓位，且必须展示对 2% 风险上限的影响。
- 自动退出顺序已固定：数据有效性、T+1 解冻、止损优先、跳空首个可观察价、正常触达预设价、成交事务、游标推进；第一目标仅使用当时可卖仓位，冻结仓位进入待退出状态。
- 订单状态机与旧确认失效规则已明确：行情、现金、持仓、订单版本或风险条件变化时，订单必须进入 `requires_reconfirmation`。
- Worker 时序已明确：30 秒行情检查、10 秒心跳、45 秒无心跳失效并允许接管。
- 所有会改变账户、订单、成交、持仓、资金、规则、租约或游标的动作均定义了事务边界。
- Codex 仅能经本地 stdio MCP 调用 Command Service，无法跳过用户确认和风控，也无法直接改数据库。
