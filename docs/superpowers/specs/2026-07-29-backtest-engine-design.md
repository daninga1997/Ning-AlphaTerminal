# Backtest Engine V1 设计规范

## 目标

在 Alpha Terminal 中新增独立的 `/backtest` 历史回测页面。回测仅使用真实历史日线，按确定规则模拟交易，不创建真实订单、不写入数据库、不影响模拟交易与现有行情链路。

## 严格边界

- 新增代码仅位于 `src/app/backtest/`、`src/app/api/backtest/`、`src/components/backtest/`、`src/lib/backtest/` 与 `src/types/backtest.ts`。
- 允许新增侧边栏 `/backtest` 导航入口；除此之外不修改现有页面、现有 API、Provider、策略引擎、模拟交易、数据完整性或分钟 K 线逻辑。
- 历史数据接口仅提供 GET，不调用 POST、PUT、PATCH、DELETE，不写数据库。
- 不返回 Mock 数据，不以不完整数据生成局部回测结果。
- 每次执行只产生内存中的报告；刷新页面后不保留结果。

## 数据接口

### `GET /api/backtest/history`

输入：

- `code`：深市主板代码，格式 `000`、`001` 或 `002` 开头的六位代码。
- `start`：`YYYY-MM-DD`。
- `end`：`YYYY-MM-DD`，且不早于 `start`。

行为：

- 只读取腾讯日线服务。
- 最多请求并返回 500 个交易日。
- 仅返回闭区间 `[start, end]` 内的已完成日线。
- 请求范围超过 500 个交易日、没有可用日线、日期格式错误或上游失败时，返回结构化错误；不静默截断，不回退 Mock。
- 返回归一化日线及只读元信息：来源、最后更新时间、数据状态、返回交易日数。

## 回测执行模型

- 只使用日线 OHLCV。
- 每日收盘后计算信号；订单在下一交易日开盘执行。
- 单次回测只运行一种策略、一只股票、一个仓位。
- 初始资金固定为 100,000 元。
- 每次买入使用全部可用现金，成交数量向下取整为 100 股整数倍。
- 同一时间最多一笔持仓，不加仓、不做空。
- 到达回测区间结束仍持仓时，按最后一个交易日收盘价结算，并标记为“区间结算”。
- 每个交易日只向策略暴露截至该日的数据，禁止未来函数。

## 回测成本假设

以下仅为回测成本模型，不表示券商实际收费：

- 买入成交价：下一交易日开盘价乘以 `1.0005`。
- 卖出成交价：下一交易日开盘价乘以 `0.9995`。
- 买卖双向佣金：成交金额的 `0.03%`，单笔最低 5 元。
- 卖出附加费率：成交金额的 `0.05%`。

## 策略

### 突破策略

- 参数 `N` 默认 20，可选范围 5 到 120。
- 买入：收盘价严格高于此前 N 个交易日的最高价。
- 卖出：收盘价跌破此前 `floor(N / 2)` 个交易日的最低价。

### 均线交叉策略

- 使用 EMA12 与 EMA26。
- 买入：EMA12 自下向上穿越 EMA26。
- 卖出：EMA12 自上向下穿越 EMA26。

### 趋势波段兼容策略

- 复用现有 `trend_swing_v1` 的日线趋势配置与日线因子定义。
- 买入：MA20 高于 MA60、收盘价高于 MA20、MA20 相比五日前上升、近 20 日动量为正且量能条件通过。
- 卖出：收盘价跌破 MA20，或 MA20 不再高于 MA60。
- 报告名称为“trend_swing_v1 日线历史适配版”。
- 不直接调用依赖实时行情、分钟线、板块和完整性权限的 `runAllStrategies`，以免伪造历史上下文。

## 报告口径

- 期末权益：现金加未平仓持仓的区间结算市值。
- 总收益率：`期末权益 / 初始资金 - 1`。
- 年化收益率：`(期末权益 / 初始资金) ^ (365 / 实际日历天数) - 1`。
- 最大回撤：每日权益相对于此前权益峰值的最大跌幅。
- 胜率：盈利平仓交易数除以全部已平仓交易数。
- 盈亏比：平均盈利金额除以平均亏损金额绝对值；无亏损样本显示“无亏损样本”。
- 交易次数：已完成的一买一卖交易数。
- 交易明细包含信号日、买入日和价、卖出日和价、股数、费用、滑点影响、持有天数、收益额、收益率和退出原因。

## 页面与交互

`/backtest` 使用独立 Backtest 组件和既有 `AppShell`：

1. 配置区：股票代码、开始日期、结束日期、策略选择；突破策略显示 N 参数。
2. 操作区：运行回测按钮；未点击前不请求历史数据。
3. 报告区：初始资金、期末权益、总收益率、年化收益率、最大回撤、胜率、盈亏比、交易次数。
4. 图表区：使用现有 Recharts 绘制资金曲线。
5. 明细区：桌面表格与移动端卡片展示逐笔交易。

请求期间只展示 Backtest 区域骨架屏，保留上一次成功报告；失败时显示区域内错误与重试按钮，不使用原生 `alert`，不暴露上游异常。

## 测试与验收

1. 历史接口只接受 GET，且不会产生数据库写入。
2. 代码、日期、500 日上限、日期范围和数据不足校验正确。
3. 三种策略的买入、卖出、无信号与边界条件正确。
4. 信号出现后只会在下一交易日成交。
5. 整手、余额不足、手续费、滑点与区间结算计算正确。
6. 指标与交易流水、资金曲线相互一致。
7. 相同日线输入得到完全相同的报告。
8. 页面覆盖初始、加载、成功、空数据、失败与移动端状态。
9. TypeScript、lint、test、build 全部通过。
10. 现有行情、分钟线、交易计划、模拟交易和数据完整性相关测试持续通过。
