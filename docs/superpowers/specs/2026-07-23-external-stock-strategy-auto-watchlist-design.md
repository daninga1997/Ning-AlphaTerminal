# 外部股票策略分析与自动观察池设计

## 目标

让所有符合 `000`、`001`、`002` 编码规则的深市主板股票都能使用 Alpha Terminal 现有策略引擎分析，并根据策略结论自动加入动态观察池。原有 20 只核心观察股继续保留。

## 范围

- `/stocks/[code]` 对符合范围的外部股票使用统一的策略详情页，不再进入仅报价和日线的研究模式。
- 策略输入支持外部股票的真实报价、日线、分钟线、市场概览和板块上下文。
- 新建持久化动态观察池，用于保存策略自动加入的股票。
- Watchlist 合并显示核心观察池和动态观察池，并清楚标记来源。

不包含自动下单、自动移除观察池、扩展到非深市主板股票，或伪造缺失的日线、分钟线与板块数据。

## 统一策略详情

详情页始终运行现有策略引擎，并按现有顺序展示：决策结论、交易计划、评分依据、技术快照、价格图表和风险条件。

外部股票的名称来自搜索和报价数据。若没有板块映射，策略输入保留空板块集合，界面明确显示“板块上下文缺失”。任何依赖板块的数据项必须标明缺失，不得用核心池的模拟板块评分替代。

日线或分钟线缺失时，完整性报告继续控制策略许可。页面显示 `data_blocked` 的具体原因，不显示伪造的买入计划、建仓区、止损或目标位。

## 自动加入规则

在每次外部股票策略分析完成后，系统依据最终交易计划决定是否写入动态观察池：

| 条件 | 结果 |
| --- | --- |
| `currentAction` 为 `focus`、`wait_for_pullback`、`breakout_watch` 或 `buy_allowed`，且不是 `data_blocked` | 自动加入或更新动态观察池 |
| `currentAction` 为 `avoid` | 不加入 |
| `currentAction` 为 `data_blocked` | 不加入 |

自动加入必须幂等：同一代码重复分析时只更新现有条目的最后分析信息，不创建重复条目。核心观察池代码不创建动态重复条目。

动态条目至少保存：代码、名称、来源、首次加入时间、最后分析时间、触发策略、最后策略动作、数据完整性状态、最近结论和最近分析日期。

## Watchlist 呈现

Watchlist 将核心观察池与动态观察池合并展示：

- 核心条目显示“核心观察池”。
- 自动加入条目显示“策略自动加入”。
- 自动加入条目展示最近策略动作、最近分析时间与数据状态。
- 现有排序、筛选和详情跳转同时适用于两类条目。

动态观察池不是新的核心池，也不会隐式改变既有 20 只核心观察股的行业映射或报告排名。

## 数据与错误处理

- 策略分析使用真实数据能力与数据完整性报告；数据不可用时返回可解释的阻断结论。
- 搜索和详情请求重复执行不会重复新增动态条目。
- 数据库写入失败不影响策略结果展示，但页面须显示“自动加入失败”，并且不宣称已加入。
- 自动加入仅由策略最终结论触发，不由搜索行为或页面访问本身触发。

## 验收与测试

至少覆盖以下场景：

1. 外部深市主板股票可以生成策略输入与策略详情。
2. 合格策略动作自动创建动态观察池条目。
3. 重复分析同一代码只更新，不重复写入。
4. `avoid` 和 `data_blocked` 不创建动态条目。
5. 核心观察池股票不会产生重复的动态条目。
6. 日线、分钟线或板块上下文缺失时，页面和策略结论如实表达缺失状态。
7. Watchlist 可以显示并识别两类观察池来源。
